# Threat model

## Scope

MCP Faultline launches local processes (fixture servers on official SDKs, the
reference server) and talks to them over stdio or loopback HTTP. It does not
contact remote MCP servers, needs no credentials, and makes no network
requests other than to `127.0.0.1`.

## Assets

* The developer's machine and environment (the harness runs subprocesses).
* Integrity of published evidence (traces, reports, reproductions).
* Upstream maintainers' time and trust.

## Threats and mitigations

| threat | mitigation |
|---|---|
| Target fixture executes arbitrary code | Targets are fixed in-repo scripts launched with argument lists (no shell). `FAULTLINE_TARGET_PYTHON` lets a user choose the interpreter on purpose. Do not point it at untrusted environments. |
| Malicious or compromised SDK release | Versions pinned exactly (`PINNED`, `package-lock.json`). The detected version is recorded in every trace, and `test_*_is_the_pinned_version` fails on drift. Dependabot proposes updates; they are not auto-merged. |
| Loopback HTTP exposure | Servers bind `127.0.0.1` on an ephemeral port and are terminated after each run. |
| Patched SDK leaking into shared caches | `scripts/fix_validation.py` builds a separate venv with stdlib `venv` + pip (copies) and refuses to edit any hard-linked file. (This rule exists because a uv hardlink once propagated an experimental patch; it was detected and reverted using RECORD hashes.) |
| Misleading evidence (fabricated or stale results) | Results are generated by the CLI, never hand-edited. Each trace carries provenance and the harness commit. `replay` re-executes a trace and compares signatures. Strict-xfail tests turn red when a pinned SDK changes behaviour, which forces the docs to be updated. |
| Over-reporting to upstream | Findings are classified as MUST violations vs SHOULD observations. Overlap with existing issues is checked and stated. Nothing is posted upstream without maintainer-process review and owner approval. |
| Secrets in traces | Scenarios contain only synthetic ids and tags. Provenance records interpreter, platform and commit, never environment variables or user paths beyond the target command. |

## Out of scope

Denial-of-service, fuzzing of remote services, and authentication testing.
Reports about an SDK's security go through that project's security policy, not
public issues.
